# Thistlevane — Art Redesign Log

Records what changed, why it changed, and which files were affected.

---

## Milestone 1 — Audit (2026-11-15)

- Completed full asset inventory: 4 characters, 15 mobs (all placeholder), 6 tilesets, 1 effects sheet
- Documented all sprite dimensions, animation specs, and technical constraints
- Identified key visual problems: no shared art identity, poor mob silhouettes, grid artifacts in tilesets
- Created: `docs/ASSET_INVENTORY.md`, `docs/ART_DIRECTION_PLAN.md`

## Milestone 2 — Art Direction (2026-11-15)

- Studied Witchbrook visual principles (warm lighting, environmental richness, character personality)
- Researched pixel art colour theory (hue shifting, warm highlights / cool shadows)
- Defined Thistlevane's unique identity: cozy medieval-rural, top-down, nature-first
- Established master palette with per-biome colour ramps
- Defined outline rules (Deep Bark #2a1f2d, 1px), lighting direction (top-left), pixel density rules
- Created: `docs/ART_BIBLE.md`

---

## Milestone 3-5 — Character redesign (state found on 2026-11-16)

- All four characters are now built from pxl sources in `assets/prototype/*-redesign.px.js`
  and exported to `assets/characters/<id>.png`
- 8 directions (4 cardinal + 4 diagonal), 6-frame idle with blink, 8-frame walk and run
- Sheets are 528x256 (22 cols x 8 rows of 24x32)
- Environment prototype tiles live in `assets/prototype/meadow-tiles.px.js`

## Milestone 6 — Combat animation, MMORPG interface, integration (2026-11-16)

### Art

- **Attack animation**, 4 frames per direction, added to all four characters
  (32 new frames each, 128 in total). Sheets grew from 22 to 26 columns
  (528x256 -> 624x256); existing columns, rows, anchors and foot offsets are
  untouched, so no other asset or map reference changed.
  The swing is an overhead chop: raise, wind up, land, recover. The pose data
  (`SWING` in each `*-redesign.px.js`) keeps the weapon clear of the body
  silhouette, because at 24x32 a blade crossing the torso reads as noise.
  Right-facing views are generated by mirroring the left ones, as the rest of
  the sheet already does.
- **Per-character weapons** so the four read apart in a fight: Rowan's short
  sword, Pip's dagger (0.75 reach), Lilac's branch wand with a glowing tip,
  Ash's lantern rod. Each is three palette entries plus a weapon config; the
  swing code itself is shared.
- **`assets/effects/combat.png`** (new): `slash` (5f), `impact` (5f),
  `target-ring` (1f). Source `assets/prototype/combat-fx.px.js`.
  The first impact drawing was a near-solid white disc that hid the creature
  being hit; it was redrawn as a six-spoke spark with a hollow core.
- **`assets/ui/icons.png`** (new): six 16x16 hotbar icons. Source
  `assets/prototype/ui-icons.px.js`. The boot and lantern were redrawn once
  each after the first pass read as a bag and a dark blob.

### Interface

- `client/index.html`: the whole HUD stylesheet, driven by a `--ui-scale`
  custom property so the chrome shrinks on small windows instead of eating
  the view.
- `client/src/ui/GameHud.ts`: player frame (portrait, name, level, title, HP,
  MP, XP), target frame (portrait, level, HP, state), six-slot hotbar with
  cooldown wipe, status overlay, control hint, dev read-out.
- `client/src/ui/CombatText.ts`: floating damage / crit / miss / XP numbers.
- `client/src/entities/EntitySprite.ts`: floating nameplate + health bar,
  white hit flash, defeated dimming.
- `client/src/combat/CombatPreview.ts` (new): client-side target, mob health,
  damage roll, cooldown, mana and XP. **Not authoritative** — the server has
  no combat yet (Milestone 4); this exists so the interface can be seen and
  judged, and is the seam where server results will replace local rolls.
- `client/src/ui/DevHud.ts`: removed, replaced by the HUD's dev read-out.
