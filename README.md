# Thistlevane

A cozy medieval pixel MMORPG for the browser. Four 500×500 zones (The Barren Grasslands, The Wastelands, Thistlevane Hollow, Frostvane Peaks) connected by portals, with wandering mobs.

## Requirements

- Node.js **22 or newer** (`node -v` to check)

## Run it

```bash
npm install
npm run dev
```

This starts the game server (port from `assets/data/game-config.json`, default 3000) and the client dev server on port 5173.
Open **http://localhost:5173** in two *separate browser windows*.

**Controls:** WASD or the arrow keys to move. Hold **Shift** to run. Tap a direction to turn on the spot.
**Tab** or a click targets a creature, **Esc** clears it, **Space** (or hotbar slot 1) swings your weapon.
Movement keys can be changed in `game-config.json`.

> Combat is a **client-side preview**: the server has no combat system yet, so damage, mob health,
> cooldowns and XP live only in your browser tab and other players do not see them.
> See `client/src/combat/CombatPreview.ts`.

> Use separate windows, not two tabs in one window. Browsers throttle hidden tabs.

Optional URL parameters:

| Parameter | Example | Purpose |
|---|---|---|
| `name` | `?name=Rowan` | Your display name (sanitized by the server) |
| `character` | `?character=monk` | Character id from `assets/data/characters.json` (random if omitted) |
| `server` | `?server=ws://192.168.1.10:3000/ws` | Connect to a different game server |

To test from another device on your LAN, run `npm run dev:server` in one terminal and `npm run dev --workspace client -- --host` in another. Then open `http://<your-PC-IP>:5173`.

## Scripts

| Command | What it does |
|---|---|
| `npm run dev` | Server + client with hot reload |
| `npm test` | Unit tests + multiplayer integration tests (real WebSocket clients) |
| `npm run typecheck` | TypeScript checks for all packages |
| `npm run build` | Production build of the client into `client/dist` |

## Layout

```
assets/   ALL content + tuning (config, maps, characters, effects, images) — read by server AND client
shared/   protocol, config/content types + validation, movement rules, Tiled map model
server/   authoritative Node.js game server (ws), fixed-tick simulation
client/   Phaser 4 + Vite browser client
tools/    world generator (Node), placeholder art generators, vendored Codixel core
docs/     content guide + architecture decision records
```

Start with **`docs/content-guide.md`**. It covers zones and portals, elevation, mobs, changing speeds, adding characters, editing maps in Tiled, tile properties and effects. See `CHECKLIST.md` for project status.

Regenerate the zones: `node tools/world/generate.mjs --preview` (previews land in `tools/world/preview/`).

## Art

Environment art is generated by `tools/world/` on top of the Codixel core (`tools/art/codixel/`, MIT).

Combat effects and HUD icons are drawn as code with the **pxl** skill. The sources live in
`assets/prototype/*.px.js`; build one with:

```bash
node .claude/skills/pxl-pixel-art/bin/pxl.js build assets/prototype/combat-fx.px.js
```

That writes `assets/prototype/out/` (including 16x previews in `out/_preview/`), and the finished sheet is
copied to its home in `assets/`:

| Source | Output | Lives at |
|---|---|---|
| `combat-fx.px.js` | `out/combat_fx.png` | `assets/effects/combat.png` |
| `ui-icons.px.js` | `out/scenes/ui_icons.png` | `assets/ui/icons.png` |

Playable characters (Corin Ashvale + 18 classes) are hand-delivered 96×96 sheets, re-tiled into the
engine's grid layout — see "Adding a character" in `docs/content-guide.md`. Only Ashvale has combat
animations (attack/hit/death) today; the 18 classes are locomotion-only until a combat art pass lands.
`assets/data/classes.json`, `balance-framework.json` and `unlock-schedule.json` hold the class/skill
design reference for that future milestone, not yet wired into gameplay.

Mob art is still **placeholder** (`tools/art/mobs.mjs`, flagged `"placeholder": true` in `mobs.json`).
The art direction is in `docs/ART_BIBLE.md`; what changed and why is in `docs/ART_REDESIGN_LOG.md`.
